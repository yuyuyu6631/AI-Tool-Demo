# 前端重设计工作稿

> 用途：给后续前端重新设计提供统一入口。本文档不写成宣传稿，只记录当前页面事实、可改造的布局骨架、组件边界和验收口径。

## 1. 设计目标

星点评是 AI 工具 review 与 discovery 平台，核心任务不是展示品牌，而是帮用户更快判断：

1. 我现在要做的任务应该用哪类 AI 工具
2. 哪个工具更适合我的场景、预算和访问条件
3. 工具是否可靠，是否有真实评论、限制和替代选项

本轮重设计应优先提升“找工具、比工具、看风险、做决定”的效率。

## 2. 设计上下文

### 2.1 目标用户

- AI 工具重度试用者：需要快速比较新工具、价格、限制、口碑
- 内容创作者 / 运营 / 设计师：按任务找写作、图片、视频、PPT、社媒工具
- 产品 / 研发 / 创业者：需要判断工具是否能进入真实工作流
- 站点运营和管理员：需要维护工具、评论、榜单和推荐理由

### 2.2 品牌气质

- 可信：像有编辑判断的平台，不像工具广告页
- 清爽：信息密度高但不杂乱
- 稳定：能承载目录、评论、后台等长期产品能力
- 有 AI 行业感：允许局部科技感，但不能变成暗黑发光模板

### 2.3 视觉方向

- 公开站点：内容产品 + 工具目录，白底为主，局部深色 hero 可用于任务搜索心智
- 管理后台：工作台风格，信息清楚、操作密集、弱装饰
- 组件语言：圆角、边框、阴影、毛玻璃可以保留，但应降低重复卡片堆叠
- 主色：蓝色作为操作色，金色/琥珀只用于“福利、价格、亮点”类强调

## 4. 信息架构建议

### 4.1 顶层导航

建议保留 5 个一级入口：

1. 首页：任务输入与品牌入口
2. 工具库：实际可链接到 `/tools` 兼容入口或带参数的首页/搜索页
3. 场景：链接 `/scenarios`
4. 福利：链接 `/deals`
5. 同好：链接 `/matches`

后台入口、登录态、全局搜索和移动端菜单作为右侧工具区，不应挤占主导航。

### 4.2 核心用户路径

路径 A：不知道用什么工具

1. 首页输入任务
2. 进入 `/search?task=...`
3. 选择推荐场景
4. 查看场景详情和工具组合
5. 进入工具详情或对比页

路径 B：已经知道工具类型

1. 导航进入工具库/搜索
2. 使用分类、价格、访问限制、排序筛选
3. 查看工具卡片
4. 进入详情页确认评论和限制

路径 C：想找免费或可试工具

1. 进入 `/deals`
2. 按免费额度、访问限制、风险筛选
3. 进入工具详情

路径 D：管理员维护内容

1. 进入 `/admin`
2. 查看总览和待处理项
3. 维护工具、评论、榜单

## 5. 页面蓝图

### 5.1 首页 `/`

页面目标：让用户先说任务，而不是先浏览一堆工具。

推荐结构：

1. Header
2. 任务搜索 hero
3. 快速任务入口
4. 任务拆解预览或 radar 可视化
5. 场景入口带
6. 热门/最新/免费工具摘要
7. Footer

设计注意：

- 首屏只保留一个主输入框和少量高频任务入口
- hero 可以使用深色科技感，但下方内容要回到清爽白底，避免整站暗色化
- 不要把所有工具卡片塞进首页首屏
- 移动端首屏输入框、快捷任务和主按钮必须完整可见

### 5.2 搜索页 `/search`

页面目标：把自然语言任务变成可执行路径。

推荐结构：

1. Breadcrumbs
2. 任务确认区：展示“我理解你要做什么”
3. 搜索框：允许重新输入任务
4. 推荐场景列表：每项包含适用情况、下一步、避坑提醒
5. 侧栏：解释当前流程，并提供直接去工具库入口

设计注意：

- 搜索页不要直接变成工具列表页
- 场景卡片应突出“为什么推荐这个场景”
- 语音按钮如果只是占位，应弱化，不要表现为已可用核心能力

### 5.3 工具库承接

当前 `/tools` 会重定向，设计上仍需要“工具库”心智。

推荐结构：

1. 搜索和筛选条
2. 分类 chips
3. 价格、访问限制、排序筛选
4. 工具列表
5. 分页或加载更多
6. 右侧场景/榜单/提交入口

设计注意：

- URL 参数驱动逻辑不能被破坏
- 工具卡片不要只展示 logo 和简介，必须露出价格、访问限制、评分/评论证据
- 侧栏只能承接辅助决策，不应喧宾夺主

### 5.4 工具详情 `/tools/[slug]`

页面目标：帮助用户判断“要不要试这个工具”。

推荐结构：

1. 返回入口和面包屑
2. 工具头部：logo、名称、摘要、评分、官网按钮
3. 决策信息条：价格、访问方式、平台、适用人群
4. 编辑点评
5. 适用场景
6. 评论摘要和评论列表
7. 相似工具
8. 对比入口

设计注意：

- 官网按钮是主操作，但不能盖过风险信息
- 评论区需要区分编辑评论、用户评论、来源评论
- 相似工具只展示必要差异，不要重复完整工具卡片所有信息

### 5.5 场景页 `/scenarios` 与 `/scenarios/[slug]`

页面目标：按真实任务组织工具，而不是按工具分类堆列表。

列表页推荐结构：

1. 场景分类或任务入口
2. 高频场景组
3. 每个场景显示适用人群、步骤数、工具数量

详情页推荐结构：

1. 场景说明
2. 痛点和判断标准
3. 任务步骤
4. 主推工具
5. 备选工具
6. 避坑提醒

### 5.6 对比页 `/compare/[comparisonSlug]`

页面目标：让差异一眼可见。

推荐结构：

1. 对比对象头部
2. 关键结论摘要
3. 横向对比表
4. 适用场景差异
5. 价格和访问限制
6. 评论和风险证据

设计注意：

- 2 到 3 个工具是当前边界，不要设计成无限对比
- 表格移动端应转为分组卡片或横向滑动，不能压缩到不可读

### 5.7 福利页 `/deals`

页面目标：帮用户找免费、可试、折扣和低风险试用路径。

推荐结构：

1. 福利态势 hero
2. 免费/可试工具列表
3. 限制提醒
4. 全部免费工具入口

设计注意：

- 必须突出“额度、限制、商用授权、地区访问、更新时间”
- 不要把福利页做成促销广告页

### 5.8 同好页 `/matches`

页面目标：用工具兴趣和工作流标签连接相似用户。

推荐结构：

1. 人设/兴趣 hero
2. 匹配流
3. 个人资料入口
4. 打招呼抽屉或轻量互动

设计注意：

- 可以比主站更有社交感，但 Header、Footer、按钮和卡片语义要统一
- 隐私、身份和占位数据要有清楚边界

### 5.9 认证页 `/auth`

页面目标：降低登录注册阻力，同时建立可信感。

推荐结构：

1. 顶栏
2. 品牌说明区
3. 登录/注册 tab
4. 表单
5. 错误、提交中、已登录状态

设计注意：

- 社交登录未真实接入时必须是占位或弱化状态
- 表单错误要贴近字段，不要只在顶部显示笼统错误

### 5.10 后台 `/admin/*`

页面目标：让运营能高效维护内容。

推荐结构：

1. AdminShell
2. 左侧导航或顶部模块导航
3. 总览指标和待处理事项
4. 列表、筛选、编辑表单
5. 保存、删除、错误和权限状态

设计注意：

- 后台不要使用营销 hero
- 表格、表单、批量操作的密度可以高于公开站点
- 管理操作需要明确危险状态和撤销/确认边界

## 6. 组件重设计清单

| 组件 | 当前用途 | 重设计要求 |
| --- | --- | --- |
| `Header` | 全站导航、登录态、移动菜单 | 导航入口稳定，移动端不遮挡首屏核心输入 |

| `QuickTasks` | 高频任务入口 | 文案短，点击后路径明确 |

## 7. 设计令牌和样式约束

### 7.1 可复用基类

优先复用当前 `src/styles/theme.css` 中已有类：

- 页面：`page-shell`
- Header：`site-header`
- 面板：`panel-base`、`search-panel`、`aside-panel`
- 卡片：`card-base`、`card-interactive`、`card-subtle`
- 按钮：`btn-primary`、`btn-secondary`
- 标签：`chip-button`、`filter-chip`、`tag-muted`
- 首页：`home-searchbar-shell`、`home-quick-entry`、`home-tool-card`
- 认证：`auth-form-card`、`auth-input`

### 7.2 色彩约束

- 主背景以浅色为主：`#f7f8fb`、白色、轻微蓝灰
- 深色 hero 只用于首页、搜索页、福利页等少数高冲击入口
- 主操作色使用蓝色或深色按钮
- 金色只用于价格、福利、重点提示
- 避免大面积紫蓝渐变、强发光、单一暗蓝主题

### 7.3 圆角和卡片

- 普通卡片建议 12px 到 20px
- 大 hero 面板可使用 24px 到 32px
- 不要卡片套卡片；重复列表项才使用卡片
- 信息页优先用分区和留白，不要所有内容都装进浮动面板

### 7.4 排版和密度

- 首页和营销入口可以有更大的标题
- 详情页、后台、列表页标题应更克制
- 工具卡片文字最多 2 到 3 行
- 按钮、标签、评分、价格文本不能在移动端溢出

### 7.5 动效

- 交互反馈控制在 160ms 到 220ms
- Hover 只做轻微位移、边框和阴影变化
- 必须保留 `prefers-reduced-motion` 降级
- 不要用持续发光、弹跳或干扰阅读的循环动效

## 8. 响应式要求

### 桌面端

- 主内容宽度建议 1180px 到 1440px
- 目录类页面可以采用主栏 + 侧栏
- 后台页面允许更高密度，但要保持行高和点击目标清楚

### 平板端

- 侧栏应下沉或转为横向模块
- 对比表要避免过窄列

### 移动端

- Header 菜单不能遮挡或挤压核心操作
- 首页首屏必须能看到任务输入框
- 工具卡片改为单列
- 筛选项优先折叠为横向 chips 或抽屉
- 对比页可横向滑动或分工具分组展示

## 9. 重设计优先级

### P0：先改信息路径

1. 首页任务输入和快捷任务
2. `/search` 任务理解和场景分流
3. 工具详情页决策信息
4. 工具卡片字段一致性

### P1：强化决策证据

1. 评论摘要
2. 价格和访问限制
3. 相似工具差异
4. 对比页差异摘要

### P2：扩展体验

1. 福利页运营模块
2. 同好页社交互动
3. 后台批量操作和状态优化

## 10. 不要做

- 不要把 `/tools` 写成当前独立页面事实；它是兼容入口
- 不要把 `/rankings` 写成当前独立榜单页；它会重定向
- 不要为了视觉效果牺牲搜索、筛选、评论和后台链路
- 不要新增与现有实现无关的大型设计系统
- 不要修改 `archive/drawer/` 中的历史代码
- 不要把未接入能力设计成已经可用，例如第三方 OAuth、真实语音输入、限时活动运营

## 11. 验收清单

重设计完成后至少检查：

1. 首页、搜索页、工具详情、场景详情、对比页、福利页、认证页、后台页在桌面和移动端都可读
2. Header 登录态、移动菜单、全局搜索入口正常
3. 首页任务输入能跳转 `/search?task=...`
4. `/tools` 查询参数兼容重定向仍可用
5. `/rankings` 仍按当前策略重定向
6. 工具详情评论读取和提交状态未退化
7. 后台工具编辑、评论管理、榜单管理入口未退化
8. 运行 `npm run lint:web`
9. 运行 `npm run test:web -- --run`
10. 设计改动较大时运行 Playwright smoke 或截图检查
