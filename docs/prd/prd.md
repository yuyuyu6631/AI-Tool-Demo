## 1. 产品最终判断与定位

### 不做以下方向
- AI 工具导航站
- AI 工具点评社区
- AI 任务教程站
- AI 任务诊断器
- AI 交付工作台

这些方向因价值稀薄、隐私风险、成本不可控、冷启动困难等原因已被否决。

### 最终方向
**AI 工具实测证据库 + 场景选型平台**

### 一句话定义
**把社区里常见的 AI 工具问题，转化成标准化实测任务，用统一输入、统一 Prompt、统一评测维度测试多个 AI 工具，展示原始输出、问题标注、对比结论和付费建议，帮助用户在使用或付费前少试错。**

### 用户能听懂的表达
> 别人说哪个好用，星点评直接用同一个任务测给你看。

### 首页主标题
**同一个任务，看看哪个 AI 真能做好。**

### 首页副标题
星点评用公开样例实测主流 AI 工具，展示原始输出、问题标注、免费限制和付费建议，帮你少试错、少花冤枉钱。

## 2. 为什么是这个方向

核心挑战：用户为什么不问AI、不搜索、不逛社区，而要来星点评？

### 2.1 用户不缺工具列表，缺的是任务级实测对比
工具大全毫无壁垒，用户真正需要知道的是：
- 这个任务到底哪个工具更适合？
- 免费版够不够？
- 要不要开会员？
- 哪个工具宣传强但实测翻车？

### 2.2 直接问AI得到的是建议，不是证据
| 直接问 AI | 星点评 |
| --- | --- |
| 给建议 | 给实测证据 |
| 不一定可验证 | 展示输入和原始输出 |
| 每次回答可能变化 | 结果可复查 |
| 用户还要自己试 | 平台提前测 |
| 结论偏泛 | 结论绑定具体任务 |

**竞争金句：AI 给建议，星点评给证据。**

### 2.3 搜索结果分散、过时、广告多
搜索“AI 改简历哪个好”得到的是：
- 官网广告、小红书帖子、B站零散测评、SEO软文
- 没有统一输入，没有完整原始输出，没有统一评测维度，没有测试时间

**星点评是搜索结果的“验证层”，比搜索更标准。**

### 2.4 社区答案混乱，条件不统一
社区有价值，但每个人任务不同、Prompt不同、版本不同、付费状态不同，结论无法横向比较。

**产品位置：社区问题 → 平台实测 → 结构化报告 → 用户选型。**  
**社区是经验池，星点评是实测库。**

## 3. 产品核心定义

- **产品名称**：星点评
- **产品类型**：AI 工具实测证据库与场景选型平台
- **产品使命**：用标准化实测降低普通用户选择 AI 工具的试错成本和付费风险。
- **核心价值**：不是告诉用户“有哪些 AI 工具”，而是告诉用户“同一个任务下，不同 AI 工具实际表现有什么差别”。

## 4. 痛点分析

### 4.1 用户侧痛点
| 痛点 | 说明 |
| --- | --- |
| 工具太多，不知道选哪个 | 每个工具都说自己强 |
| 免费/付费边界不清 | 不知道免费版够不够 |
| 试错成本高 | 注册、测试、对比都麻烦 |
| 社区信息乱 | 结论多，但条件不统一 |
| AI 回答太泛 | 没有真实输出证据 |
| 搜索结果广告多 | 很难判断是否真实 |
| 不想上传隐私材料 | 简历、论文、项目资料敏感 |
| 怕买错会员 | 一次性任务不想乱花钱 |

### 4.2 公司侧痛点
| 痛点 | 说明 |
| --- | --- |
| 推广AI工具导航难讲价值 | “工具大全”没有说服力 |
| 缺少项目背书 | 需要能展示专业方法论 |
| 不想做纯运营号 | 需要产品形态 |
| 需要沉淀资产 | 实测数据比普通文章更有复用价值 |
| 需要后续转向依据 | 看用户关注哪些任务、哪些工具 |

## 5. 产品解决方案

### 5.1 核心思路
- 不要让用户上传自己的材料
- 不要实时调用多个大模型
- 不要承诺替用户完成任务
- 不要做泛泛工具介绍

**平台提前准备公开样例任务，对多个 AI 工具做同题实测，保存原始输出和评测结论，用户通过网站查看、对比、筛选和生成选型报告。**

### 5.2 产品闭环
```
社区/搜索/用户反馈收集高频问题
↓
转化成标准测试任务
↓
用统一输入和统一 Prompt 测试多个工具
↓
保存原始输出
↓
按统一维度评测
↓
生成实测报告页
↓
用户查看、对比、投票、跳转试用
↓
根据数据决定下次复测什么
```

## 7. 产品边界

### 7.1 做什么
- 同题实测：同一个任务测多个 AI 工具
- 原始输出展示：保留工具完整输出
- 横向对比：按维度比较工具表现
- 问题标注：标出废话、夸大、逻辑弱、格式问题
- 免费/付费建议：判断免费版是否够用
- 工具对比：按任务比较工具，不做虚假总榜
- 选型报告：根据任务和预算生成推荐
- 复测机制：工具更新后重新测试
- 用户反馈：收集“有帮助/不可信/想看更多”

### 7.2 不做什么
| 不做的事项 | 原因 |
| --- | --- |
| 大而全工具库 | 同质化严重 |
| 用户上传真实论文/简历 | 隐私风险高 |
| 实时多模型生成 | 成本不可控 |
| AI 自动评审用户材料 | 误判风险高 |
| 论文降AI率 | 学术风险高 |
| 社区点评 | 冷启动难 |
| 总分排行榜 | 容易失真 |
| 保证可交付 | 责任过重 |
| 复杂登录收藏 | V1 没必要 |

## 8. V1 MVP 范围

### 8.1 V1 唯一验证目标
**用户是否愿意查看同一任务下多个 AI 工具的真实输出对比，并基于实测结果进行工具选择。**

### 8.2 规模
6 个任务 × 4 个工具 = 24 组原始输出

### 8.3 首批任务
| 任务 | 选择原因 |
| --- | --- |
| 简历项目经历改写 | 学生和实习生刚需，易展示差异 |
| 答辩PPT大纲生成 | 学生场景，结果易对比 |
| Excel 数据分析结论 | 职场新人常见，展示逻辑能力 |
| 会议纪要整理 | 办公高频，展示结构化能力 |
| 短视频脚本生成 | 内容场景，看创意和实用性 |
| 测试用例生成 | 与测试背景强相关，差异化 |

### 8.4 首批工具
通用文本类：ChatGPT、Claude、DeepSeek、Kimi  
后续可扩展：Gamma、Canva、WPS AI、剪映、即梦、可灵、NotebookLM、Perplexity、Gemini  
**V1 不要贪多。**

## 9. 页面架构

### 9.1 首页
**目标**：3秒内让用户知道这是“AI 工具同题实测平台”。  

**内容结构**：首屏标题 → 副标题 → 查看实测任务按钮 → 对比 AI 工具按钮 → 本周实测卡片 → 热门任务入口 → 工具对比入口 → 评测方法论说明 → 无需上传个人材料提示 → 公司/团队背书  

**关键文案**：
- 标题：同一个任务，看看哪个 AI 真能做好。
- 副标题：星点评用公开样例实测主流 AI 工具，展示原始输出、问题标注、免费限制和付费建议，帮你少试错、少花冤枉钱。
- 按钮：“查看实测任务” / “对比 AI 工具”
- 信任提示：无需上传个人材料，所有测试均基于公开样例。

### 9.2 任务实测列表页
**目标**：让用户选择想看的任务。  

**内容**：任务分类、任务卡片（含参与工具、最后测试时间、一句话结论）、查看实测按钮  

**卡片示例**：  
4 个 AI 工具改写测试实习经历，谁更适合写进简历？  
ChatGPT / Claude / DeepSeek / Kimi 同题实测  
最后测试：2026-04

### 9.3 任务实测详情页（核心页面）
**固定结构**（像测试报告，不像文章）：
1. 一句话结论
2. 本次测试任务
3. 测试输入
4. 使用 Prompt
5. 参与工具
6. 测试时间
7. 工具状态（免费版/付费版/模型版本）
8. 各工具原始输出
9. 横向对比表
10. 问题标注
11. 适合谁用
12. 不适合谁用
13. 免费版是否够用
14. 是否值得付费
15. 最终建议
16. 用户反馈
17. 相关实测

### 9.4 工具对比页
**目标**：让用户按任务场景比较工具。  

**结构**：选择工具A → 选择工具B → 选择任务场景 → 查看对比结果 → 查看相关实测 → 查看免费/付费差异 → 查看最终建议  

**不做总分榜**，只做场景化结论，例如：  
- 做简历：Claude 更稳，DeepSeek 更适合中文初稿
- 整理长文：Kimi 更适合
- 复杂推理：ChatGPT/Claude 更稳
- 预算敏感：DeepSeek/Kimi 更友好

### 9.5 选型报告页
**目标**：给用户一个可保存、可分享、可导出的工具选择结论。  

**用户输入**：任务类型、预算、能否接受付费、更看重什么（质量/速度/免费/中文/隐私）、使用水平  

**生成输出**：推荐工具组合、推荐理由、引用的实测报告、免费方案、付费建议、不建议购买项、适合人群、下一步操作  

**技术实现**：用规则和模板生成，不需要实时调用大模型。

### 9.6 方法论页
**目标**：建立信任。  

**内容**：
- 我们如何测试 AI 工具？
- 为什么不用总分排行榜？
- 为什么展示原始输出？
- 为什么标注测试时间？
- 为什么不用用户隐私材料？

**评测原则**：统一任务、统一输入、统一 Prompt、统一维度、保留原始输出、标注测试时间、允许结论更新、不做绝对承诺。

## 10. 评测标准体系

### 10.1 通用评测维度
| 维度 | 说明 |
| --- | --- |
| 完整度 | 是否完成任务要求 |
| 准确性 | 是否出现明显事实错误 |
| 可用性 | 是否能继续修改或直接参考 |
| 废话比例 | 是否有空话、套话、泛泛表达 |
| 结构化 | 是否层次清楚 |
| 场景匹配 | 是否符合任务目标 |
| 风险点 | 是否夸大、编造、误导 |
| 人工修改成本 | 还需要改多少 |

### 10.2 专项任务评测维度
**简历任务**：真实可信、岗位相关能力、具体动作、结果表达、是否夸大、HR 可读性、便于面试展开  
**PPT 任务**：结构完整、逻辑顺、页数合理、讲述节奏、适合答辩/汇报、空泛标题、可转成实际页面  
**Excel 分析**：字段理解、图表建议合理性、结论依据、是否误读、下一步分析、数据口径提醒  
**测试用例**：覆盖完整、前置条件清楚、步骤可执行、预期结果明确、正常/异常区分、边界值、可落表

## 11. SEO 与拉新策略

### 11.1 SEO 页面类型
- **工具对比词**：ChatGPT 和 Claude 哪个适合写简历？Kimi 和 DeepSeek 哪个适合整理论文？Gamma 和 Canva 哪个适合做PPT？
- **任务实测词**：AI 改简历哪个好？AI 做答辩PPT哪个好？AI 写测试用例哪个靠谱？
- **避坑决策词**：学生党要不要买 ChatGPT Plus？Gamma 免费版够不够？AI 工具免费版够用吗？

### 11.2 SEO 页面结构
每个 SEO 页面嵌入实测结果，结构：问题标题 → 一句话结论 → 测试任务 → 原始输出对比 → 横向评测 → 免费/付费建议 → 查看完整实测 → 相关工具对比  
**与普通 SEO 文章形成差异化。**

## 12. 推广策略

### 12.1 公司推广口径
**不要说**：“我们做了一个 AI 工具推荐网站。”  
**要说**：“我们做了一个 AI 工具真实任务实测平台。通过统一任务、统一输入、统一 Prompt 和统一评测维度，对主流 AI 工具进行场景化测试，帮助用户在使用和付费前降低试错成本。”

### 12.2 短内容传播标题
- 我用 4 个 AI 工具改同一份简历，差别很明显
- 同一个答辩 PPT 任务，ChatGPT、Claude、DeepSeek、Kimi 谁更稳？
- Kimi 和 DeepSeek 整理长文资料，谁更适合学生党？
- AI 写测试用例实测：哪个工具最少废话？
- 学生党别乱买 AI 会员，先看这几个任务实测

## 13. 数据指标体系

| 反馈投票率 | 用户是否愿意评价结论 |
| 复测请求提交率 | 用户是否想看更多测试 |

### 13.2 结果反馈选项
每个实测页底部放置：
- A. 帮我省了试错时间
- B. 我还想看更多同类任务
- C. 结论不可信
- D. 我已经决定用哪个工具

**这是比点赞更有价值的数据。**

## 14. V1 成功标准与失败标准

### 14.1 成功标准（假设 1000 次访问）
- 首页 → 实测列表点击率 ≥ 15%
- 实测详情页 → 原始输出展开率 ≥ 30%
- 实测详情页 → 工具对比点击率 ≥ 10%
- 选型报告生成率 ≥ 5%
- 反馈投票率 ≥ 3%
- 工具官网跳转率 ≥ 3%

核心成功判断：用户有没有看原始输出、做工具对比、觉得省了试错时间。

### 14.2 失败标准与应对
出现以下情况，**不要继续加功能**，回头检查任务选择、标题力度、内容深度、展示方式：
- 用户只看首页，不进实测页
- 进实测页但不展开原始输出
- 只看结论，不看对比
- 没人生成选型报告
- 没人反馈“省了试错时间”
- SEO 进来后跳出率极高

## 15. 商业化判断

- 公司 AI 应用展示入口
- SEO 内容验证项目
- AI 工具评测资产沉淀项目
- 后续商业化试验基础

**后续可能商业化方向**：
| 方向 | 说明 |
| --- | --- |
| 企业 AI 工具选型报告 | 给公司/团队做工具采购建议 |
| 定制任务评测 | 针对行业任务做测试 |
| 工具导流 | 给工具官网导流或联盟 |
| 高级评测报告 | 免费版/付费版/版本迭代对比 |
| 培训材料 | 基于实测结果做使用培训 |

**现在不要讲大商业故事。**

## 16. 风险与兜底策略

| 风险 | 兜底方案 |
| --- | --- |
| 评测结论被质疑 | 展示原始输入、原始输出、Prompt、测试时间 |
| 工具更新太快 | 标注最后测试时间，设置复测机制 |
| 结论过于主观 | 用“适合/不适合”代替绝对排名 |
| 评测工作量大 | V1 只做 6 个任务 × 4 个工具 |
| SEO 起量慢 | 配合公司推广和短内容分发 |
| 被复制 | 长期沉淀输出库、任务样例库、评测规则库 |
| 用户不信任 | 建立方法论页，展示完整测试过程 |
| 内容过期 | 页面提示“该实测结果可能已过期，等待复测” |

## 18. 第一版核心页面样例

**任务：简历项目经历改写**

**页面标题**：4 个 AI 工具改写测试实习经历，谁更适合写进简历？

**首屏结论**：  
Claude 更适合做最终润色，DeepSeek 更适合中文初稿，ChatGPT 输出完整但容易写满，Kimi 适合整理长材料但简历表达不够锋利。

**测试输入**：  
用户是一名软件测试实习生，参与后台管理系统测试，负责测试用例编写、接口测试、缺陷提交和回归验证，使用 Postman、JMeter、禅道、MySQL 等工具。

**统一 Prompt**：  
请把下面这段实习经历改写成适合软件测试岗位简历的项目经历，要求真实、清晰、不过度夸大，突出测试动作、工具使用和结果。

**对比维度**：真实可信、岗位匹配、动作具体、结果表达、废话比例、是否夸大、HR 可读性

**页面内容要素**：
- ChatGPT / Claude / DeepSeek / Kimi 原始输出
- 横向对比表
- 问题标注
- 最终建议
- 免费/付费建议
- 用户反馈

## 19. 最终决策建议

### 建议执行
**AI 工具实测证据库与场景选型平台**

### 不建议执行
- AI 工具导航
- AI 工具社区
- AI 任务交付工作台
- 用户上传材料生成结果
- 论文降AI味工具
- 泛泛任务教程站

### V1 唯一验证目标
**用户是否愿意查看同一任务下多个 AI 工具的真实输出对比，并基于这些对比做工具选择。**

### 最终一句话
**星点评不是让用户来问“哪个 AI 好用”，而是让用户看到“同一个任务下，不同 AI 到底输出了什么”。**  
这就是搜索、AI、社区都很难稳定提供的东西。
